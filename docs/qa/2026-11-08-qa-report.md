## The owner's acceptance test: "after Send, show how long until all emails are sent, show the time, analytics work"

**Today**
- After Send: toast "Campaign started sending!", the wizard closes, the user is on the campaigns list (`src/pages/campaigns/page.tsx:276-283`).
- The list never refreshes by itself: no `refetchInterval` (`page.tsx:189-192`), refetch-on-focus is off app-wide (`src/components/providers/query-client.tsx:10`). The "Sending" badge pulses until a reload.
- The Recipients column shows `totalRecipients`, which during a send is the count sent so far, not the audience (`page.tsx:957`, `server/lib/campaign-sender.ts:483`).
- `GET /api/campaigns/:id/progress` exists (`server/routes/campaigns.ts:395-409`) but **nothing calls it**; it is not in `src/lib/api.ts`.
- Only Analytics detail refreshes (every 20s, `src/pages/analytics/detail.tsx:42`), and it shows "Sent: N/A" until the end (`detail.tsx:124`). The analytics list says "Not sent yet" for a sending campaign (`src/pages/analytics/page.tsx:77`). "View Report" exists only for `sent` (`page.tsx:978`).
- The only time hint is a 10-second toast when the daily limit is smaller than the audience (`campaign-sender.ts:257-259`).

**Missing**
1. A progress screen to go to after Send, polling every 3-5s while `sending`.
2. A `/progress` that can give an ETA: send rate, start time (`MIN(campaign_recipients.sentAt)`), daily budget left, "continues at HH:MM", expected finish.
   - `rate = floor(MaxSendRate x 0.9)` (about 12/s); if `queued <= budget`: `eta = now + queued / rate`;
     otherwise the rest resume at (oldest sent in last 24h + 24h) at `DAILY_SEND_LIMIT` per day.
3. **"About 15 minutes" is true only up to about 10,000 recipients.** `DAILY_SEND_LIMIT` is 10,000 (`server/lib/send-limits.ts:11`), so 50,000 takes about 5 days, mostly sleeping in 10-minute waits (`campaign-sender.ts:383-388`), with a frozen count on screen.
4. No time estimate before sending in step 5 (`page.tsx:1993-2033`).
