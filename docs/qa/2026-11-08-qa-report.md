**Missing**
1. A progress screen to go to after Send, polling every 3-5s while `sending`.
2. A `/progress` that can give an ETA: send rate, start time (`MIN(campaign_recipients.sentAt)`), daily budget left, "continues at HH:MM", expected finish.
   - `rate = floor(MaxSendRate x 0.9)` (about 12/s); if `queued <= budget`: `eta = now + queued / rate`;
     otherwise the rest resume at (oldest sent in last 24h + 24h) at `DAILY_SEND_LIMIT` per day.
3. **"About 15 minutes" is true only up to about 10,000 recipients.** `DAILY_SEND_LIMIT` is 10,000 (`server/lib/send-limits.ts:11`), so 50,000 takes about 5 days, mostly sleeping in 10-minute waits (`campaign-sender.ts:383-388`), with a frozen count on screen.
4. No time estimate before sending in step 5 (`page.tsx:1993-2033`).

## Re-check, 8 Nov (dev 94a07d8) and what it led to

The `qa-engineer` agent re-checked every finding: 13 fixed outright, the rest partly. It also found new faults, all
fixed in the next commit:

- **N1 (critical):** a campaign paused, given a new list and sent again still went to the old list's queued people.
  Dispatch now deletes queued/failed rows no longer in the audience (test).
- **N2:** Resume/Send on a paused campaign whose worker was asleep in a limit wait refused or did nothing; it now
  flips back to sending and that worker carries on.
- **N3:** a Pause during the last chunk left "paused, 0 waiting" forever; it now ends as sent (test).
- **N5:** the lease is now claimed during the 1-second wait and awaited before the next chunk (no chunk sent after
  losing it, no unhandled rejection).
- **N4:** a click within two minutes of sending (a link scanner) no longer counts as an open (test).
- **N6:** the progress page and the estimate say when another campaign is sending at the same time.
- **Finding 7 rest:** test sends are tagged `test` and the webhook never files them under a real campaign.
- **11, 18, 19, N7-N9:** one toast for a new draft; whole-number ids and no raw error text on 500s; the step-5
  footer wraps; Schedule only where the server allows it; wording; paused campaigns show sent-so-far in analytics.

Still open: the SES-quota 10-minute wait isn't shown on the progress page (the countdown can pass zero), the
two-campaign case shares one SES rate without a shared limiter, and none of the new SQL has run on real TiDB.
